## Запреты движка

**`stagger: {from: 'random'}` использовать нельзя.** Он дёргает `Math.random()`, а рендер обязан
быть детерминированным — иначе два прогона дадут разные кадры и повторный рендер сломает уже
смонтированный ролик. Замена: перестановка индексов через LCG с фиксированным сидом и явный
`delay` каждому элементу.

```js
// детерминированная перестановка вместо from:'random'
let seed = 20260901;
const rnd = () => (seed = Math.imul(seed, 1664525) + 1013904223 >>> 0) / 4294967296;
const order = chars.map((_, i) => i);
for (let i = order.length - 1; i > 0; i--) {
  const j = Math.floor(rnd() * (i + 1));
  [order[i], order[j]] = [order[j], order[i]];
}
order.forEach((idx, rank) => tl.to(chars[idx], { opacity: 0, duration: 0.05 }, 1.05 + rank * 0.007));
```

**Твин `letterSpacing` линтер блокирует** (`gsap_non_transform_motion`): reflow снапит глифы по
целым пикселям, и раздвижка получается ступенчатой. Раздвижку трекинга делать per-glyph `x` —
каждая буква едет на `(i − (n−1)/2) × шаг`, интерполяция становится субпиксельной.

**Начальные состояния — немедленным `gsap.set()`, не `tl.set(..., 0)`.** Иначе кадр 0 покажет
нескрытое состояние (`gsap_timeline_set_initial_hide`) — на рендере это первый кадр со всем
содержимым сразу.

**`pathLength="1"` вместе с GSAP не работает.** Нормализованная длина пути — штатный способ
рисовать линию через `stroke-dashoffset`, но GSAP пишет числовые значения с единицами, и
`strokeDasharray: 1` уезжает в `1px`. Линия остаётся невидимой почти весь твин, а под конец
выскакивает целиком; на выборке кадров это читается как «ветка не нарисовалась».

Считай реальные длины и ставь их в фазе `gsap.set`:

```js
paths.forEach((el) => {
  const len = el.getTotalLength();
  gsap.set(el, { strokeDasharray: len, strokeDashoffset: len });
});
tl.to(paths, { strokeDashoffset: 0, duration: .65, ease: "power2.inOut" }, .6);
```

Длины у веток разные, но нормализованный прогресс одинаковый, так что синхронность
нескольких линий сохраняется — это важно там, где одновременность и есть содержание сцены.

**Плагины SplitText и FLIP не подключать** — платные и сетевые, а рендер должен работать офлайн.
Разбивку текста по словам и символам писать руками в `<span>`, реверстку блока — анимацией `y`
на контейнере с заранее посчитанной величиной.

**Несколько твинов на один селектор линтер считает перекрытием.** Если словам заголовка нужны
разные стартовые состояния (рецепт кадра 0), не пиши по твину на слово — схлопни в один твин
со `stagger`, а разные начальные значения задай отдельным `gsap.set()` по элементам.

**Seek-safety.** Никаких `gsap.ticker`, `requestAnimationFrame` или `onUpdate` со скрытым
состоянием: рендер перематывает таймлайн произвольно, а не проигрывает подряд. Всё считать заранее
и класть в единый `paused`-таймлайн. Исключение — прокси-объект, из которого в `onUpdate`
пересчитывается несколько взаимозависимых свойств: он seek-safe, потому что состояние живёт
в самом твине, а не снаружи.

## Цвет и светлая тема

**Не твинь цвета, заданные через rgba с альфой поверх цветной подложки.** GSAP интерполирует
прозрачность, и середина перехода уходит в посторонний тёплый оттенок — на стоп-кадре это выглядит
как баг вёрстки. Держи непрозрачные значения, а дискретные состояния переключай `tl.set`, не твином.

**Твин `brightness` на белом фоне невидим.** Подсветку строки делать сменой подложки, а не фильтром.
Но и подложку проверяй: `--surface-2` (#EDEFF3) на `--blue-100` (#E8ECFD) отличаются по светлоте
меньше чем на процент — переключение формально есть, а глазом не видно. Добавляй к тому же `tl.set`
акцентное кольцо (`inset 0 0 0 2px rgba(46,88,234,.30)`) или тень.

**`--faint` (#9AA0A9) почти везде валит AA:** на `--paper` даёт 2.4:1, на `--surface-2` — 2.29:1,
на `--blue-100` — 2.24:1. Для любого читаемого текста бери `--muted`. `--faint` остаётся только
для декора, который зритель не читает.

**Расфокусированный бэкплейт: `opacity .22` — это цифра с тёмного референса.** На светлой бумаге
белые карточки при .22 исчезают полностью. Нужно ~.34 при blur 22px плюс явная граница карточкам.

**`--coral` (#F0584E) на `--paper` даёт 2.8:1 и не проходит AA.** Для текста бери `#D94A3E`,
для заливок и точек оригинальный `--coral` нормально. Но `#D94A3E` — не универсальная замена:
на более светлых подложках он даёт 4.2:1 и тоже не проходит, там нужен `#C8443A`. Проверяй
по конкретной подложке, а не подставляй по памяти.

**Многоступенчатый радиальный градиент даёт видимый бандинг кольцами.** Три стопа с падением
в `transparent`, а не десяток. Стоп `rgba(...,0)` того же цвета вместо `transparent` даёт серый
ореол на части движков.

**Блюр бандинг не убирает.** Это заблуждение стоило нескольких итераций: кольца остаются даже при
`blur(80px)`, потому что причина не в резкости переходов, а в 8-битной квантизации на большой
площади. Размытие перераспределяет те же ступени, а не добавляет промежуточных значений.

Лечится дизерингом — тонким шумом поверх пятна:

```html
<svg width="0" height="0" style="position:absolute">
  <filter id="grain">
    <feTurbulence type="fractalNoise" baseFrequency="0.8" numOctaves="1" seed="7"/>
    <feColorMatrix type="saturate" values="0"/>
  </filter>
</svg>
```

```css
.blob::after {
  content: ""; position: absolute; inset: 0;
  filter: url(#grain); opacity: .035; mix-blend-mode: overlay;
  pointer-events: none;
}
```

`seed` фиксированный — шум детерминирован. Непрозрачность держи в районе .03–.05: этого хватает,
чтобы разбить ступени, и мало, чтобы шум был заметен сам по себе.

Оценивать бандинг только по полноразмерному PNG: JPEG-контакт-лист его усиливает, а после
компрессии в MP4 он обычно пропадает вовсе. Если на PNG кольца слабые — можно не трогать.

**Стекло не читается поверх светлого UI.** Правило «стекло только поверх видео» верно,
но скринкаст — тоже видео, и на белой доске или светлом интерфейсе полупрозрачная панель
превращается в мутное пятно без границ: размывать там нечего, всё и так белое. Для оверлея
над светлым интерфейсом бери плотную карточку — `--surface`, рамка `--line`, заметная тень
(`0 14px 40px rgba(20,22,26,.22)`) и цветная кромка слева. Стекло остаётся для съёмки
и тёмных экранов.

**Свечение на светлой теме** — `multiply` или растущий `drop-shadow`. `screen` на белом не даст ничего.

## Швы и переходы

**Главное правило: свяжи физически то, что должно двигаться вместе.**

Когда обе стороны перехода едут в ОДНУ сторону (вертикальный или горизонтальный push) — это одно
движение. Сложи сцены встык в контейнер двойной высоты и двигай рельс целиком: `yPercent: 0 → -50`,
один ease на обе. Velocity match получается по построению.

Зеркальные `power4.in` / `power4.out` на двух независимых слоях для такого шва НЕ работают:
на середине уходящая сдвинута на 3%, входящая на 97%, и читается это как «B накрывает A».

Когда стороны лежат на РАЗНОЙ глубине и расходятся (zoom-through по оси Z) — наоборот, зеркальные
кривые правильны, а общий контейнер приём сломает.

**Ease для push-рельса: `power3.inOut`.** `power4.inOut` укладывает почти весь ход в 0.2 с из 0.55
и читается рывком.

**Zoom-through на 1920 не читается от одного `scale` плоскости**: 13% роста глазом не видно, а
ранний блюр добивает остаток и получается расфокус-кроссфейд. Нужен параллакс ВНУТРИ уходящей
сцены — её содержимое едет быстрее своей плоскости и выходит за кромку кадра. Блюр при этом на
`power1.in`, чтобы слой успел заметно вырасти, пока ещё резкий.

**Blur на шве** — `keyframes: [0, 14, 0]` с пиком ровно в точке склейки, одним фильтром на общий
контейнер, а не по фильтру на слой.

**Никакого fade на push-шве.** Opacity обеих сцен держится на единице весь переход, иначе приём
превращается в кроссфейд.

## Связи, импульсы и маски

**Отрезок-связь без импульса на светлой бумаге почти не сообщение.** 3px `--line-2` показывает,
что два узла связаны, но не показывает направление. Стрелок в дизайн-системе нет, поэтому
направление несёт импульс, едущий по линии.

**Импульс из одного градиентного блика не читается.** Замер на сцене «фронтенд → API → бэкенд»:
тонкий блик по 3px-рельсу на полноразмерном PNG выглядит синим пятнышком, приём формально есть,
глазом его нет. Рабочая конструкция — три слоя: яркая сплошная «голова» (~54×7, `--blue`,
`box-shadow`-свечение), за ней сужающийся хвост по высоте рельса (~190px) и мягкое радиальное
свечение под `blur(5px)`. Тогда на стоп-кадре это летящий пакет, а не подсветка линии.

**Мягкий хвост подсвечивает торцы рельса на парковке.** Пока импульс ждёт своего проезда за
кромкой контейнера, его свечение вылезает в зазор между блоками — на кадре 0 висят синие огрызки.
Гасить геометрией (отогнать дальше) значит укоротить видимый ход. Правильно — два `tl.set`
на `opacity` ровно в начало и конец проезда, обе точки на границе кадра: `Math.round(t * fps) / fps`.

**Порт на линии должен лежать ВНЕ маскирующего контейнера.** Импульс живёт внутри `#link`
с `overflow: hidden`, и квадрат-порт, положенный туда же, срезается по высоте линии —
от 44px квадрата остаётся 3px полоска. Порт — соседний элемент, не потомок маски.

**Маска для подрезки текстового блока считается от высоты текста, а не от видимого окна.**
`mask-image: linear-gradient(...)` с процентными стопами, повешенная прямо на абзац в 430px,
при окне в 170px уводит затухание далеко за нижнюю кромку, и подпись поверх ложится на
полностью читаемую строку. Решение — отдельный слой `inset: 0` внутри окна фиксированной
высоты, маска на нём, стопы в пикселях от низа:

```css
#prompt-clip {
  position: absolute; inset: 0;
  mask-image: linear-gradient(to bottom, #000 calc(100% - 108px), transparent calc(100% - 22px));
}
```

Чистая полоса под подпись тогда одинаковая при любой высоте окна, и блок в развёрнутом
состоянии заполнен текстом, а не пустотой.

## Композиция и масштаб

**Кадр 1920×1080 больше, чем кажется.** Первая версия почти всегда выходит мелкой. Сразу бери
верхние ступени шкалы: 70px Unbounded для обложечной строки, 54px Onest 800 для заголовка сцены,
24px минимум для основного текста. Иконки — 220–260px, а не 90px.

**Марка не конкурирует с сообщением.** Вордмарк или логотип — служебный мелкий элемент (~30px
с трекингом). Доминирует то, что нужно прочесть.

**Пустота должна быть воздухом, а не дырой.** Асимметричная композиция с диагональю читается лучше,
чем аккуратно центрированная группа посреди пустого листа. Привязывай блоки друг к другу: верх
текстового блока к верху соседней иконки (с поправкой на полулидинг заголовка) — именно это
превращает два объекта в сетку.

**Обводка монолинейных иконок.** Канонические 2px при крупном кегле выглядят волосяными —
на иконке 250px бери 3px в viewBox.

**Перспектива.** `rotateY 4°` на крупном объекте не видна вообще, нужно 7–8°.

**Маркер (highlighter)** вешать на `<span>` вокруг слова с `position: relative`, а не задавать
фиксированной шириной в px — иначе он обрывается посреди следующего слова при любой правке кегля.
Полоса должна быть выше line-box текста, иначе срезает верх букв.

**Приём, который не читается, надо усилить, а не оставить «формально верным».** Перетекание
заливки на светлом фоне почти не видно — добавь вертикальный маркер фронта. Шов, у которого обе
стороны пусты в середине, показывать нечего — дай сценам контент в зоне стыка.

## Проверка

**`npm run check` не ловит композиционные провалы.** Он проверяет линт, рантайм, layout, motion
и контраст — но не скажет, что кадр пустой, текст мелкий или элементы стоят как попало.
Снимай кадры и смотри их глазами:

```bash
../node_modules/.bin/hyperframes snapshot . --frames 8 -o snapshots
```

Контакт-лист `contact-sheet.jpg` — для общей оценки. **Спорные места смотри полноразмерным PNG:**
на JPEG-превью слабые контуры градиентов выглядят как бандинг, которого в композиции нет, а мелкий
кегль читается мельче реального.

**Точечные кадры важнее равномерных.** Вся сложность живёт внутри переходов — снимай
`--at 1.45,1.55,1.675,1.8` вокруг шва, а не только восемь равномерных кадров.

**Ассерты в сайдкаре ловят то, что глаз пропускает между кадрами.** `staysInFrame` на объекте,
который уезжает под камерный `scale`, отлавливает обрезку кромкой автоматически — включая
промежуточные версии, где на выбранных таймкодах всё выглядело нормально. Вешай его на любой
элемент, который двигается к краю кадра.

**Проверяй детерминизм** на кадре, где есть псевдослучайность: два снимка одного таймкода должны
дать одинаковый SHA-256.

**Аудит ругается на сами приёмы** — размытый бэкплейт, перекрытие сцен в шве, приглушённые соседи
в карусели. Но сначала убедись, что это приём, а не настоящая проблема: реальные находки чини,
а не глуши. Заглушенная честная находка хуже, чем warning в отчёте.

Каждый опт-аут выключает **строго свою проверку** — не вешай наугад:

| Атрибут | Что именно глушит |
|---|---|
| `data-layout-allow-overflow` | выход за границы — вылеты на входе и уходе |
| `data-layout-allow-overlap` | намеренное наложение текста на текст |
| `data-layout-allow-occlusion` | элемент, который по замыслу закрывает текст |
| `data-layout-allow-caption-zone` | только `caption_zone_collision` в зоне нижней трети |
| `data-layout-ignore` | элемент декоративный и **не аудируется вообще**, включая контраст |

`data-layout-allow-overlap` **не наследуется**: помечать надо конкретный участник наложения,
никогда не сцену и не корневой враппер, — иначе перестанут проверяться все вложенные коллизии.
`data-layout-allow-caption-zone`, наоборот, действует на потомков.

`data-layout-ignore` — самый широкий: он снимает и контраст тоже. Вешай его только на то, что
зритель не читает (фоновые пятна, сетка, декоративные цифры-подложки). Если повесить его на
элемент с текстом, контрастная проверка этого текста молча исчезнет из отчёта.

**Любой оверлей поверх текста глушит его аудит.** Виньетирующие кромки, затемняющие слои,
«стекло» поверх карточек — всё это заставляет аудит считать текст перекрытым, и число проверок
рушится (замер: 113 → 41 от одного виньетирующего слоя). Если эффект нужен только визуально,
делай его `mask-image` на контейнере, а не отдельным перекрывающим элементом: выглядит так же,
а текст остаётся проверяемым.

**Дискретные переключения выравнивай по сетке кадров.** `tl.set` в момент, не попадающий на границу
кадра, размазывается квантованием: два `tl.set` на «2.45» дают 2–3 кадра промежуточного состояния
вместо одного. Считай позицию как `Math.round(t * fps) / fps` и разводи пару на ровно один кадр —
для смены палитры это разница между чистой передачей акцента и заметным провалом.

## Автоматическая проверка движения

`check` умеет проверять **намерение движения** на том же перемотанном таймлайне, который использует
рендер, — это ближайший автоматический аналог «отрендерь и посмотри». Ловит то, что не видит
выборка по кадрам: вход, мимо которого перемотка проскочила; сломанный порядок stagger; элемент,
уехавший за кадр посреди твина; замерший план.

Положи рядом с композицией сайдкар `*.motion.json` — `check` подхватит его сам, без флагов:

```json
{
  "duration": 5.5,
  "assertions": [
    { "kind": "appearsBy", "selector": "#item-01", "bySec": 1.0 },
    { "kind": "before", "a": "#item-01", "b": "#item-02" },
    { "kind": "staysInFrame", "selector": ".card" },
    { "kind": "keepsMoving", "withinSelector": ".scene" }
  ]
}
```

`keepsMoving` особенно полезен в этом стиле: закон «ничего не стоит на месте» он проверяет
автоматически, и он же ловит `motion_frozen` — замерший холд, если push-in кончается раньше сцены.

**Чего ассерты НЕ покрывают** (в 0.8.22 их всего четыре):

- **«должен выйти за кадр» не выражается.** `staysInFrame` на уходящем объекте падает по построению,
  так что с него его приходится снимать, а сам выход проверять кадрами. То же с объектом, который
  стартует за кромкой.
- **SVG-анимации проходят мимо.** `stroke-dashoffset` не двигает боксы, поэтому `keepsMoving`
  не видит ни рисующихся линий, ни ленты света.
- **`keepsMoving` на клипе считает замершим время ДО его `data-start`.** Вешай его на `#root`
  или на контейнер, живущий всю сцену, а не на клип, который приходит в середине.
- **`staysInFrame` на враппере размером в холст падает по построению.** Сквозной наезд
  `#stage → scale 1.022` формально выводит границы полноэкранного контейнера за кромку кадра,
  и ассерт срабатывает на приёме, а не на дефекте. Вешай его на конкретный блок внутри сцены
  (карточку, строку, узел), а не на обёртку, живущую во весь кадр.
- **Очень приглушённый элемент считается «ещё не появившимся».** `appearsBy` требует `opacity ≥ 0.5`,
  так что на строке, которая по замыслу висит на `.45` (уход в глубину), ассерт придётся снять.

Ставь их на то, что реально входит и удерживается, а уход и декор проверяй глазами.

**CLI не глобальный.** `npx hyperframes` в корне падает с «Missing script». Внутри проекта работают
`npm run check` и `npm run render`, снаружи — `./node_modules/.bin/hyperframes`.

## Приёмка: чем врёт контакт-лист (снято на ролике «watch», 12 сцен)

**Сетка 3×3 систематически занижает воспринимаемый масштаб.** На контакт-листе каждая
плитка ~600px, и нормально свёрстанная сцена выглядит мелкой схемой в белом поле. На этом
ролике две сцены были забракованы за «всё мелкое», и одна из двух правок оказалась лишней —
при сравнении в полный кадр с исходником масштаб был в порядке.

Правило: **приём и композицию оценивай по полноразмерному кадру** (`review/frame-*.png`),
рядом с кадром исходника, в который вставка встанет. Контакт-лист годится ровно для одного —
проверить, что соседние кадры отличаются друг от друга.

**Пустой низ кадра — не всегда дефект.** Если в исходнике поверх вставки ляжет камера-PiP,
нижняя треть обязана быть пустой. Прежде чем гнать агента «заполнять кадр», посмотри,
как устроены соседние кадры автора.

**Сквозной дрейф и мелкий nudge за событие не считаются.** Они не читаются на стоп-кадре.
Если два соседних кадра контакт-листа неразличимы — там мёртвый промежуток, сколько бы
твинов формально ни стояло в таймлайне.

## Служебная графика, которая читается как баг интерфейса

Дважды за один ролик агенты ставили декор, который зритель прочтёт как случайно попавший
в кадр интерфейс:

- **прямоугольник с квадратами по углам** вокруг элемента («о чём говорю сейчас») —
  это в точности рамка выделения в Figma. Лечится тем, что вместо рамки нужный узел
  выводится из расфокуса: приём начинает работать дважды вместо служебной подписи;
- **стопка серых скруглённых полос** как «абстрактная графика» — это skeleton-заглушка
  недогруженного экрана.

- **дорожки прогресс-баров, стоящие в кадре до заливки** — те же серые полосы, и на кадре 0
  они читаются как незагруженный экран. Приводи дорожку вместе с её подписью, а не раньше:
  когда над полосой уже стоит чип, она перестаёт быть заглушкой;
- **пилюля фиксированной ширины под текст в два слова** — две короткие фразы в широкой белой
  полосе читаются как пустые строки таблицы. Списочные пилюли делай `width: max-content`,
  а не по общей сетке.

Отдельный случай с той же природой — **приглушённый блок «нечитаемого» текста**. Он нужен
в сценах вроде «вот весь промпт, его не грузят целиком», и соблазн нарисовать его серыми
полосами велик. Полосы дадут skeleton; нужен настоящий текст, приглушённый и подрезанный
маской, — видно, что там слова, просто их не читают. Кегль там можно опустить ниже минимума
дизайн-системы (22px) и пометить блок `data-layout-ignore`: это намеренно нечитаемый декор.

Проверка простая: если элемент можно спутать с чужим UI, он не декор, а шум.

## Keep-out сквозного якоря — это прямоугольник

Формулировку «не правее x и не ниже y» агенты читают как две запретные полосы и загоняют
всю композицию в верхний левый угол. Писать в спеке надо явно: запрещена область, где условия
выполняются **одновременно**; левее границы по x можно опускаться до низа кадра, выше границы
по y — уходить до правого края. На этом ролике из-за такого прочтения три сцены из двенадцати
пришлось перекомпоновывать.

## mix-blend-mode внутри трансформированного контейнера

`#stage` со сквозным наездом (`scale`) — изолированный контекст наложения: `mix-blend-mode:
multiply` у ребёнка смешивается с прозрачным `#stage`, а не с фоном под ним, и белая подложка
сгенерированной картинки видна квадратом. Белый фон переводить в альфу заранее (формула —
в `techniques-observed.md`, «Картинка-герой из генерации»).

## Контакт-лист 3×3 занижает кегль — приёмку делать по полному кадру

На листе 3×3 кадр 1920 ужат до ~640px, и подписи 30–40px выглядят как 18–24. Приёмщик по листу
отправил на доработку сцены с нормальным текстом. Проверять конец сцены полноразмерным кадром
(или кропом панели), лист — только для ритма и пустот. Реальная частая беда другая: сборщики
сжимают героя в иконку ~120px и оставляют половину панели пустой.

## Синтезированный SFX без средних частот не слышен на ноутбуке

«Удар штампа» из синуса 52–120 Гц на пике −3.5 dB, но выше 200 Гц — −13 dB: на динамиках ноутбука
звук пропадает целиком («звук отказа исчез»). В ударе должен быть щелчок 1.5–4 кГц (шумовой
всплеск с затуханием ~10 мс) + тело 150–250 Гц. Проверка: `highpass=f=300,volumedetect` — пик
не ниже −6 dB.

## codex exec в цикле `while read` съедает stdin

При генерации картинок пачкой `codex exec` без `< /dev/null` читает остаток списка промптов,
и после первой волны цикл завершается. Всегда `codex exec … < /dev/null`.

Итог по штампу: чисто синтезированный удар (aevalsrc) автор забраковал целиком — «видно, что
сгенерированный». Рабочий вариант — слой из реальных сэмплов бандла: `key-press` (щелчок) +
`pop` на `asetrate×0.55` (тело удара) + 0,5 с `impact-bass-2` с low-pass 900 Гц и −8 dB (хвост).
«Плохой исход» — два `pop` вниз (`asetrate×0.78`, через 150 мс `×0.6`). Синтез из синусов для SFX
не использовать.

## Вторая камера, нарезанная по keepRanges, уплывает на секунды к концу

Нарезка iPhone (24 fps VFR) через `trim`+`concat` по 339 кускам и `fps=30` в конце дала файл на
6,5 с длиннее звука: каждый стык добавляет от −2 до +3 кадров, и сдвиг копится (0,5 с на 1-й минуте,
6,3 с на 27-й). Формулой (ceil до кадра 24 fps) не описывается. Рабочий путь: померить сдвиг на
каждом куске — кадр исходника в середине куска против 36 кадров результата вокруг предсказания
(160×90, минимум MAE, `-hwaccel videotoolbox`, 6 потоков — 1,5 мин на 339 кусков), и читать камеру
по карте `t_cam = t + off[кусок]` (последовательное чтение с пропуском кадров). Первые 10 с при
этом выглядят идеально — проверять синхрон в середине и в конце.

## Бандл SFX media-use лежит не в ~/.claude/skills

`assemble_v4.py` ищет звуки в `~/.claude/skills/media-use/audio/assets/sfx`, а локальная копия
скилла в этом репо содержит только `manifest.json`. Сами mp3 (whoosh, pop, click, ping, typing…)
лежат внутри пакета hyperframes / media-use (найди `skills/media-use/audio/assets/sfx/` под своей установкой).
Перед сведением проверь, что файлы на месте: `ls <bundle>/*.mp3`.

## Прозрачные оверлеи поверх камеры

`hyperframes render . --format mov` даёт ProRes 4444 `yuva444p12le` — альфа работает, если во
фрагменте `html, body, #root { background: transparent !important } .bg { display:none }`.
Проверять наложением на реальный кадр камеры, а не на белом.

## Полнокадровый `<video>` в композиции перекрывает всю графику при рендере

HyperFrames 0.8.22: `<video class="clip">` на весь кадр + карточки/субтитры поверх. `snapshot`
показывает всё верно, а `render` в MP4 отдаёт голое видео — графики нет ни в одном кадре,
`z-index` не помогает (шортс «юрист → ChatGPT», 2026-10-02). Лечение: видео в композицию не
класть, рендерить графику прозрачным слоем (`--format mov`, фон `transparent`) и накладывать
ffmpeg: `[base][gfx]overlay=0:0:format=auto`. Всегда проверяй кадр готового MP4, а не снапшот.

## Склейка кусков с PCM-звуком уезжает от видео

`-ss/-to` на HEVC VFR iPhone даёт видео на кадр длиннее звука; 20 кусков через concat-demuxer —
рассинхрон 0,4–0,8 с к концу. Резать с `-frames:v N` и `-af apad,atrim=0:N/30`, видео concat'ом
перекодировать с `setpts=N/30/TB`. `apad` + `-shortest` не использовать — пишет бесконечный звук.

## Грабли пакета сцен NikeTheHuman (6 сцен, 2026-10-04)

- **`check` не видит шрифты из `tokens.css`.** `@font-face` подключены через `@import`, и линтер выдаёт ошибку `font_family_without_font_face`. Её получили 5 сцен из 6. Объявляй нужные `@font-face` прямо в `<style>` композиции с путями `./assets/fonts/...`. Для Unbounded пиши `font-weight: 200 900`, иначе 800 рисуется синтетически.
- **`class="clip"` не скрывает корневой `<svg>`.** Такой SVG виден с кадра 0. Оборачивай его в `<div class="clip">`.
- **`fromTo` в середине таймлайна** по умолчанию сразу применяет from-значения, и элемент виден с кадра 0. Ставь `immediateRender:false`. Свойство, которое есть только во from, тогда не применится совсем, так что задай его отдельным `tl.set` на момент входа.
- **Не ставь `will-change` на камеру-контейнер.** Chrome растеризует слой в начальном масштабе, и текст на 3x мылится.
- **Блюр и камера на разных обёртках.** Блюр вешай на неподвижную внешнюю обёртку, `scale` — на внутреннюю. Иначе радиус блюра умножается на масштаб.
- **Окно тишины перед ударом надо резать в файлах.** Хвосты SFX из бандла длинные (у `impact-bass` 2,1 с) и залезают в паузу. Обрезай всё до окна через `atrim` + `afade`, громкость клипа тут не спасает. Проверка готового MP4: `ffmpeg -ss T -t 0.3 -i out.mp4 -af volumedetect`, должно быть около −90 dB.
- **`alimiter`** по умолчанию поднимает уровень обратно к 0 dB. Пиши `alimiter=limit=0.9:level=0`.
- **Линтер ругается на `${}` в `querySelector`** (`template_literal_selector`). Собирай селектор конкатенацией строк.
- **Файл композиции длиннее 300 строк** даёт `composition_file_too_large`. Скрипт вынести нельзя, так что сжимай разметку.
- **Кадр по номеру.** `ffmpeg -ss 4.17` берёт первый кадр с pts ≥ 4.17 и может показать не ту сторону склейки. На склейках и вспышках бери кадр через `select=eq(n,N)`.
