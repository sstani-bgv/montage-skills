# Сборка одного шортса

Один вызов — один MP4 1080×1920. Всё детерминированное лежит в скриптах;
твоя работа — запустить нужный, посмотреть результат кадрами и починить, если
видно брак.

## Запуск

```bash
uv run --with pillow --with numpy --with 'opencv-python-headless<5' python3 \
  skills/shorts-build/scripts/render_all.py \
  --plan /tmp/shorts/plan.json --only s03 --out /tmp/shorts/renders
```

Без `--only` соберёт все записи плана подряд. Схема `plan.json` — в шапке
`render_all.py`.

`--only` принимает и несколько id через запятую. После исправления общего кода
или плана пересобирай только провалившиеся ролики: `--only s02,s05`.

`opencv-python-headless<5` — не придирка: в OpenCV 5 выкинули
`cv2.CascadeClassifier`, на котором держится трекинг головы.

## Раскладки

Раскладку выбирает план, но понимать их надо, чтобы читать результат.

| | что в кадре | субтитры | когда |
|---|---|---|---|
| `split` | преза сверху 1000×563, вебка снизу 1000×550 | в зазоре, y≈928 | исходник = экран + PiP |
| `cam` | камера на весь кадр 9:16 | y≈1240 | исходник = камера целиком |
| `broll` | экран во всю ширину 1000×750 на своём размытом фоне | y≈1290 | исходник = экран без вебки |
| `auto` | переключает предыдущие по ходу | едут вместе с геометрией | внутри отрезка есть переключения |

**`cam` берёт центральные 9:16 ПОЛНОГО кадра, а не вставку.** Это не мелочь:
поставь `cam` на кусок со скринкастом — и соберётся шортс, где в центре кадра
экран, а человека нет ни в одном кадре. Взять кадр из вставки вместо этого
нельзя, апскейл выходит шестикратным и лицо плывёт (`references/gotchas.md`).
Соблазн возникает там, где в `split` мёртвый верхний слот; лечится это выбором
другого момента, а не сменой раскладки. Рендер на такое теперь падает, но лучше
не доводить.

Геометрия кадра — в `references/layouts.md`. Геометрия **исходника** (где окно
экрана, где PiP) не зашита в код: она приходит из `calib.json`, который делает
`/shorts-plan`. Если правишь константы кропов руками — ты чинишь не там.

Одно исключение: `patch_src` (источник заливки для замазки PiP) можно
переопределить прямо в записи плана. Заливка — это средний цвет куска кадра из
`patch_src`, а экран в разных местах лонга разный, поэтому один источник на весь
ролик где-то попадает в тон, а где-то кладёт светлую кляксу на тёмный интерфейс.
Подбирать по цвету окружения заплатки, а не по яркости.

## Что делает камера

**`cam` — трекинг головы и рук** (`track_cam.py`). Haar-детектор лица плюс карта
движения дают одну сглаженную траекторию окна 9:16: говорит спокойно — окно
поджимается, машет руками — расширяется, центр едет за головой с лёгким уводом
в сторону движения. Диапазон зума 0.84–1.0 от высоты исходника: шире нельзя,
9:16 из 16:9 это максимум 608×1080, дальше отъезжать физически некуда.

**`broll` — проезд по материалу** (`kenburns_path` в `compose.py`). Скрипт
находит блоки контента на слайде по карте краёв, сортирует их в порядке чтения
(полосы сверху вниз, внутри полосы слева направо) и ведёт окно: подъехал к
блоку, подержал, переехал к следующему. Один блок — медленный наезд вместо
проезда.

**`auto` — швы.** Кадр собирается покадрово (`compose.py`), поэтому прямоугольники
карточек — функции времени: вебка не пропадает рывком, а сворачивается по
высоте, преза в тот же момент разворачивается на её место. Переход split → cam
получается сам собой: окно вебки лерпится от PiP-кропа к полному кадру, то есть
вставка разворачивается в камеру.

Если автоматический классификатор намеренно отключён для talking-head исходника,
но внутри есть короткие смонтированные вставки, запись плана может задать
`layout_overrides`: непрерывный список абсолютных таймкодов с `cam`/`broll`/
`split`. Для `layout: auto` он имеет приоритет над классификатором. Это штатный
путь для крупного показа встроенных 3D- и игровых демонстраций.

## Проверка результата

Рендер отдаёт файл, даже когда собрал ерунду, поэтому проверка обязательна.

```bash
uv run --with 'opencv-python-headless<5' --with numpy --with pillow python3 \
  skills/shorts-build/scripts/qa.py \
  --video /tmp/shorts/renders/s03.mp4 --plan /tmp/shorts/plan.json --id s03
```

Скрипт делает контактный лист и гоняет автопроверки: живая ли вебка в карточке
и держится ли она весь шортс, есть ли в кадре человек (для `cam`), наложились ли
субтитры, не выглядит ли угол b-roll подозрительно вялым. Ненулевой код возврата
— значит что-то поймалось. Что именно проверяется и почему проверка угла только
советует, а не судит, написано в шапке `qa.py`.

Проверка вебки называет **таймкод худшего кадра** — иди смотреть именно туда.
Чаще всего это вставка, уехавшая из фиксированной рамки на пост-наезде: две-три
секунды интерфейса приложения вместо комнаты.

Для всей пачки используй агрегатор:

```bash
uv run --with 'opencv-python-headless<5' --with numpy --with pillow python3 \
  skills/shorts-build/scripts/qa_batch.py \
  --plan /tmp/shorts/plan.json --renders /tmp/shorts/renders
```

Он сохраняет `qa-report.json`, называет только проблемные id и печатает готовую
команду их адресной пересборки. Для `layout_overrides` QA обязательно берёт
кадры до, внутри и после каждого 0.46-секундного шва; равномерный контактный
лист такие короткие дефекты часто пропускает. Также он проверяет геометрией,
что хук не лежит поверх крупной b-roll-вставки.

**Автопроверки ловят только грубые поломки — контактный лист всё равно смотри
глазами.** На нём видно то, что машине не формализовать: камера в b-roll стоит на
тексте, а не в пустом поле; на швах в обоих слотах правильный контент; субтитры
не наезжают на лицо; хук не закрывает то, ради чего кадр взят.

Типовые поломки и их причины — в `references/gotchas.md`, загляни туда до того,
как лезть в код.

## Правка субтитров

Распознавание врёт, особенно к концу длинного ролика. Реплики лежат прямо в
`plan.json` как `[начало, конец, текст]` — правь текст там и пересобирай тот же
`--only`. Тайминги не трогай: они от пословного транскрипта и попадают в речь.

## Где что лежит

- `scripts/frames.py` — разметка кадров по типам, общая с `/shorts-plan`
- `scripts/make_short.py` — раскладки split/cam/broll на ffmpeg, субтитры, хук и
  финальная плашка тизера (`outro` в записи плана, `--outro` в CLI: та же
  карточка в том же слоте, въезжает за 2,4 с до конца и стоит до последнего кадра)
- `scripts/compose.py` — покадровый сборщик `auto`: швы и проезд по материалу
- `scripts/track_cam.py` — OpenCV-трекинг головы и рук
- `scripts/render_all.py` — точка входа, читает план
- `scripts/qa.py` — контактный лист и автопроверки собранного
- `scripts/qa_batch.py` — единый JSON-отчёт пачки и список адресной пересборки
- `assets/fonts/` — Onest Black и ExtraBold, кириллица; локальные, чтобы рендер
  не зависел от того, что установлено в системе
- `references/layouts.md` — геометрия кадра и почему именно такая
- `references/gotchas.md` — грабли, на которых этот пайплайн уже стоял
